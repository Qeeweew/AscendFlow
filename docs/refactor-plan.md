# 编译流程重构计划

本计划按最新指令执行：**先完成结构重构，再分析编译性能。** 不用跨编译结果缓存、算子特判、扩大超时或恢复旧求解器绕过合同缺口。一次编译内的不变事实应建立一次并复用。状态及运行证据只在[状态页](refactor-progress.md)登记。

## 1. 收敛一条编译链路

```text
DSL/source
  → retained native结构与SSA地址
  → 物理访问、ownership、值与输入合同
  → 精确逻辑值流 + 已绑定dispatch上的物理生命周期
  → 逻辑通知
  → 事件域 → 生命周期与进展 → bank/ID
  → 最终物理IR
  → ASC → CANN
```

已完成的结构调整：普通 `compile()` 只接受 DSL/source；旧物理输入分支和公共 `autosync/verify_plan/emit_asc` 已删除。后端读取最终 IR 中的真实条件、event SSA 和通知，不再单独解释动作表。被替代的planner、过渡实现及旧物理IR直接删除，不保留历史实现目录。

测试和基准消费者统一迁至当前产物。公共入口切换与代码删除本身不代表新路径已获得全部功能资格。

## 2. 值、存储和循环接口的重构

源码顺序混合固定 RAW/WAR/WAW 的旧递归构造器已删除。当前分工是：

1. `logical_valueflow` 一次建立精确 read→writer、代次、条件 KILL/UPDATE。未绑定输入仍是 Boundary，不由同步补成初始化。`mad_first` 的首 clear 与后续 RMW 使用原语条件访问合同。
2. `storage_packets` 从这些值证明中识别闭合 private 生命周期；`storage_word` 只推导给定排步的 PLE 相邻关系；`storage_lifetimes` 连接实际最后 reader 与下一覆盖。不是生成源码 WAR 后选择性删除，也不把读改绑到 dispatch 最近的 writer。
3. PLE 的每条关系共用实际循环的 consumer ordinal `j`，source 为 `j-distance`，入口/出口以 membership guard 表达。静态边界不另造脱离该循环的有限时钟；distance 可负。运行期长度不展开。
4. `structured_dependencies` 只编排两个阶段，后续 selection / EventDomains / progress / lease / ID 共用一条链。旧 `access_frontier` 有限求解器、carrier 类型和专属测试已直接删除；端点/FIRST/LAST 类型及硬件反例留在当前表示。

资格边界：目前只对精确 private cell、无跨 packet/跨代 RAW、同 offset 连续 stage、完整初始覆盖的 packet 授权独立重排。不将 streaming envelope 当作单次完整覆盖；外部可见状态和递推仍保留真实顺序约束。外层接口必须保持，只有无外部访问且无重复父循环的 root-private scratch 允许更换首末接口。更广的条件/动态 ownership 需要新的证明，不能凭 private 放宽。

通用反例已覆盖完整临时值换序、同 Vector 的值覆盖拒绝、真实 release 删除后的 WAR、首次 clear/后续 RMW，以及短循环/负 distance。共享 L0C 子循环已完成事件复用、有限最终IR和CANN资格；默认 FA 完整构建尚未获得当前资格，具体失败阶段见状态页。

## 3. 当前事件接口收尾

共享 L0C 的存储接线已改为实际 `QK(j) → PV(j−1) → QK(j+1)`，读版本不变；旧错误的 `PV(j−1) → QK(j)` 不再产生。当前小例已完成 progress 和跨父调用的 consume→reuse 证明。

事件候选必须以实际 dispatch step 为范围，按端点的逻辑坐标加直接 parent stage offset 转换；内层 stage 不能挪用为外层 offset。旧的只向前候选会漏掉 PV(j−1)。此外，width=1 在 prologue 可能没有返回路径：应该由有限条件图得出该宽度未成立，再按原资源规则考察下一宽度，而不是反复枚举无关未来路径直至预算耗尽。

路径证明内部已替换为一份 owned 条件端点图，节点保留完整坐标和参与者、边保留真实 queue/controller 条件与已选事件效果。必要的反向可达性只排除图上无路径的节点，不能把条件未知当成不成立；最终仍需路径条件覆盖整个复用域。旧前向搜索实现已删除，不保留第二套 fallback，不提高预算，不跳过配对或原式定义性。

进展处理现拆为区域合同、数学条件、端点与顺序事实、稀疏连通关系、局部 rank 和组合编排。替代的 dense 消元、编排器内端点/rank 方法和类型出口直接删除，测试不经兼容入口调用。一个调用共享条件 owner；端点owner持有完整绑定和父调用事实，组合器只连接这些关系。原始有序执行 guard 与数学条件集合分开；消去节点后实际删除其入出边。通知及既有端口投影规则保留；本轮替换路径条件表示时同步明确新的工作计数合同。

整数事实现在拥有完整有序前提context及惰性派生的差值/原始约束，递归不反复哈希前提或重建相同表达式。固定输入诊断的第一个子区域由28.52秒降至8.20秒，四个内部子区域均完成；source到EventDomains由22.42秒降至17.88秒。随后一次公共FA构建在125.44秒明确失败：父区域接口的路径条件展开超过64个DNF备选，尚未进入CANN。不能把失败耗时当成功编译指标，也不继续其他候选。

原 progress 对固定 finite 端点和 stream 的联合投影仍有保守支持边界；不能将逐边存在投影相乘视为共享同一 ordinal 的联合证明。当前 PLE 统一时钟避免拆散本就属于一个循环的关系，不宣称实现了任意联合投影。

路径条件表示现已直接替换：

- 每对端点保存一个共享布尔激活根，消元计算 `old OR (incoming AND outgoing)`；不在接口生成时把AND分配到全部OR备选上。保留非空边界自环，不补零长度完成关系。
- 原始有序 `ActionGuard` 仍用于定义性与直接见证；数学激活公式不覆盖它。导入整棵公式时共用真实ancestor binding，区分case、participant和generation，不把公式等价当作joint projection或exact证据。
- 先在全部may边上做既有rank尝试，仅有环时才按需查询整个激活公式。UNKNOWN保留；finite环要排除所有OR可能，stream仅在uniform条件上分支。组合接口仍不提供完成或lease证据。
- 原“64个已存DNF备选”已随旧表示退场，不能伪称它与新DAG节点数等价。保留SCC分支64和region总工作100000，条件查询的显式搜索状态限为64；构造、查询和分支共同记账。此处是计数合同的明确替换，不把两种不同的计数作倍率比较。旧DNF容器、回调和计数已删除。
- 独立有限布尔可达性、7级二选一路径、跨代绑定、inexact、controller和预算反例已通过。真实双AIV嵌套CV暴露了逐关系映射同一共享子图的重复工作；现按同一已验证变换批量映射整个公式forest，空替换直接复用原根，此回归恢复。
- 所有消费者只使用forest映射入口：编排器的区域导出、按完整绑定分组的child导入、rank的uniform投影。保留sharing是表示合同，不能在消费时重新按树展开。接下来以有界阶段诊断及公共FA构建验收，不能仅以小图测试替代真实链路。

## 4. 收尾产品组织和功能资格

- 直接删除被替代的planner闭包及旧API专属测试。原语合同只接收几何，ASC只读取最终SSA；硬件反例迁至当前IR与独立模型，不保存旧实现。
- 基准消费者读取当前产物；结构模板数、算法工作量、实际运行期请求和设备流量分别标识，缺失计数明确报告。
- 测试分别承担输入合同、变换保持、实际IR破坏、独立有限执行语义和CANN构建；历史oracle不算新source资格。
- 使用同一公共链路验收双缓冲Vector、Cube/Fixpipe、嵌套/CV及默认FA。保留源算法、缓冲和排步合同；两个AIV共用一份body，用runtime sid区分。
- 每次完整算子构建最多300秒，超时清理整个进程组并停止该批候选。先定位并处理实际阻塞，再恢复对应资格构建，不直接重试或继续下一候选。
- 最终IR、ASC和实际CANN产物必须相互对应。当前debug_verify仅检查IR结构，不能充当独立同步证明。

当前主干代码组织、单一路径和旧职责退场已经落实；向量 prefix 基准也改用公共构建入口，统一300秒期限和成功产物发布。默认FA及设备资格仍需独立完成，不以小例或历史产物替代。

## 5. 结构改造落地后分析编译性能

固定当前源码、选项和输入；对成功产物记录IR/ASC，对未完成构建先记录实际停止阶段和有界诊断。测量各阶段工作量和耗时。分别考察native模板、物理分区、region边界、逻辑通知及资源关系数；runtime长度作为变量，不按执行次数展开。

已定位的重复工作收敛为同一 `IntegerFacts` 环境、owned前提/派生事实、`ProgressEndpoints` 的完整绑定和一次调用拥有的数学合取。DNF接口展开已直接移除，接下来核算端点候选、首次条件证明、共享公式消费和消元工作量。状态量不由runtime次数决定；稠密消元仍可能是立方规模，条件查询仍可能组合增长。额外通用结构key包装在实测中回归，已完整撤掉；现有表达式结构比较的潜在展开成本仍是明确边界，不能声称hash命中就保证常数时间。

用新进程的实际完整构建衡量效果，不用跨编译命中、减少验证范围、换算子排步或静默fallback作为改善证据。编译性能通过后再恢复算子性能工作，比较AscendC/ACLNN、profiling及硬件理论指标。
