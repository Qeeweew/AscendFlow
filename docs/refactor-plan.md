# 编译流程重构计划

本计划按最新指令执行：**先完成结构重构，再分析编译性能。** 不用跨编译结果缓存、算子特判、扩大超时或恢复旧求解器绕过合同缺口。一次编译内的不变事实应建立一次并复用。状态及运行证据只在[状态页](refactor-progress.md)登记。

## 1. 收敛一条编译链路

```text
DSL/source
  → retained native结构与SSA地址
  → 物理访问、ownership、值与输入合同
  → sequence / branch / loop依赖
  → 逻辑通知
  → 事件域 → 生命周期与进展 → bank/ID
  → 最终物理IR
  → ASC → CANN
```

已完成的结构调整：普通 `compile()` 只接受 DSL/source；旧物理输入分支和公共 `autosync/verify_plan/emit_asc` 已删除。后端读取最终 IR 中的真实条件、event SSA 和通知，不再单独解释动作表。被替代的planner、过渡实现及旧物理IR直接删除，不保留历史实现目录。

测试和基准消费者统一迁至当前产物。公共入口切换与代码删除本身不代表新路径已获得全部功能资格。

## 2. 当前重点：把事件合同补完整

本阶段处理**随uniform参数变化的父循环激活域**。最小例：子循环长度为`m>=1`，父代次为`p`，某个slot在子循环内存在的条件是`m > (p*m)%2`。`m=1`时只在偶数父代次出现，`m>=2`时每代出现。单一区间/固定residue不能同时表达它；目前已用整链参数分区和多余数窗口表达。真实双slot进入生命周期后仍有条件覆盖缺口，不修改输入下限或把非空条件丢掉。该问题与FA名字、query含义、runtime迭代展开无关。

本阶段按以下顺序推进，已接通部分与当前缺口见下文及状态页：

1. 保留原始membership、选中坐标的非空前提以及父代次平移，不先把它们压成单窗口。只对同一实际耦合周期所需的uniform条件进行有限划分，不能把不相关slot周期作笛卡尔积。
2. 每个条件分区内建立精确窗口及存在投影；证明分区互斥且覆盖原激活域。短长度与完整周期的边界来自模算术规则，不来自算子名或某组shape。
3. lease与ordinal消费这个有条件的域，保持同一逻辑通知的配对、银行及最终drain。不能把各分区当成互不相关的新通知而绕开跨段消费/复用。
4. 父进展组合保留实际分区条件，仍只消费child接口；不复制运行历史。计数须报告周期分区、接口关系、不同前提数量，不能只报最终图点数。
5. 用上述纯整数反例、带slot的通用DSL及真实默认FA逐层验收，再测成功编译的耗时。未实现前不增加空接口或支持标记，不恢复旧求解器。

参数域、case-aware lease记录及条件进展已经接通。当前重点是实际消费路径的完整条件覆盖：某条通知自己的域无需分区，但它的复用可能由不同参数和slot相位下的不同peer通知保障。当前bridge只接受前提直接蕴含的peer条件，因此安全地拒绝未知；后续必须为所有可行分支留下consume→next Set证据，不能任选一个“可能”peer。真实双slot中，m=4时g=0与g=1分别只能通过两条不同WAR通知建立下一同ID使用的路径，必须覆盖两者；这不是死锁证据。若增加条件证明，只允许沿实际交互细分，不建立不同通知的全局笛卡尔积，也不重跑未改变的访问/依赖事实。

### 激活域与循环窗口

`EventDomains` 一次建立实际端点、队列、参与者和 Set/Wait 激活配对。`EventWindow` 必须与实际 membership 等价，提供有条件的首末成员、同ID后继和存在投影。metadata 不能比实际发出的指令更窄；未知 carry、动态稀疏guard或未证明的别名不能静默忽略。

从内向外使用已证明的 child 存在投影构造 parent 窗口，保留共享坐标的关联。零次路径不计算没有定义的LAST；数学表达式正确也不能替代实际i64中间运算安全。

### 生命周期与资源

`event_lifetimes.py` 只处理实际消费到下一次复用的路径，使用上述窗口；不再分析内存依赖。区分有限调用内与下一次调用，不能把child出口视为全部退休。

分配器只维护 bank、ID、配置预留及最终 drain。有限通知共享ID必须留下真实 consume→next Set witness；不能把尚未实现的共享证明报成硬件容量下界。禁止为分配方便增加Scalar gate或全局barrier。

### 条件进展

`event_progress.py` 按实际region调用归属组合阻塞/发布接口。source与consumer来自不同parent代次时必须归属parent，不能误当child内部。

必须顺序用于reuse证明；可能阻塞不能遗漏，也不能丢掉其成立条件。child总结不导出虚假的异步完成。parent不能把每个内部通知的FIRST/LAST独立拼成零步图，也不再重复证明已由同一实际循环覆盖的义务。

内部stream与finite boundary已分开；本region的queue输入/阻塞输出接口已接通，仅将ancestor拥有匹配的实际通知保留到父层。父层只组合子接口，本地native、窗口及rank保留为witness。跨调用由拥有时钟的祖先按真实坐标连接，不复制子层native或新增另一套调用实例图。

先完成动态LAST死锁、短循环正例和嵌套接口反例，再集成实际例子。有限模型仅是独立回归，不能替代任意规模证明。

## 3. 收尾产品组织和功能资格

- 直接删除被替代的planner闭包及旧API专属测试。原语合同只接收几何，ASC只读取最终SSA；硬件反例迁至当前IR与独立模型，不保存旧实现。
- 基准消费者读取当前产物；结构模板数、算法工作量、实际运行期请求和设备流量分别标识，缺失计数明确报告。
- 测试分别承担输入合同、变换保持、实际IR破坏、独立有限执行语义和CANN构建；历史oracle不算新source资格。
- 使用同一公共链路验收双缓冲Vector、Cube/Fixpipe、嵌套/CV及默认FA。保留源算法、缓冲和排步合同；两个AIV共用一份body，用runtime sid区分。
- 每次完整算子构建最多300秒，超时清理整个进程组并停止该批候选。先定位并处理实际阻塞，再恢复对应资格构建，不直接重试或继续下一候选。
- 最终IR、ASC和实际CANN产物必须相互对应。当前debug_verify仅检查IR结构，不能充当独立同步证明。

当前主干代码组织、单一路径和旧职责退场已经落实；在该结构上处理重复整数证明和端点绑定后，嵌套CV已恢复完整构建。默认FA及设备资格仍需独立完成，不以小例或历史产物替代。

## 4. 结构改造落地后分析编译性能

固定当前源码、选项和输入；对成功产物记录IR/ASC，对未完成构建先记录实际停止阶段和有界诊断。测量各阶段工作量和耗时。分别考察native模板、物理分区、region边界、逻辑通知及资源关系数；runtime长度作为变量，不按执行次数展开。

已定位的重复工作收敛为同一 `IntegerFacts` 环境和完整端点绑定事实；表达式节点保存结构hash/排序信息，替换按共享节点遍历。状态量由静态模板、接口和不同前提决定，不由runtime次数决定。复杂度仍需计入各region的接口两两关系、图消去及不同有序条件集合；不能笼统称整个同步算法线性。结构排序的相等比较仍可能遍历子结构，不宣称所有表达式操作都是常数时间。

用新进程的实际完整构建衡量效果，不用跨编译命中、减少验证范围、换算子排步或静默fallback作为改善证据。编译性能通过后再恢复算子性能工作，比较AscendC/ACLNN、profiling及硬件理论指标。
